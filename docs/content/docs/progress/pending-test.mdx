# Pending Tests

The current release needs manual verification in these areas:

- Windows desktop build: double-clicking `build-desktop.cmd` in the repository root (or `build-desktop-mirror.cmd` on slow networks) should check Bun / Node.js, install missing dependencies, and produce `desktop/release/infinite-canvas-<version>-setup.exe`; `cd desktop && npm ci && bun run dist` should also work. Electron should be copied from `node_modules/electron/dist` directly, without the `win-unpacked.tmp` rename `EPERM`. The installed app should open the canvas, save model settings, paste images from the clipboard, and open external links such as documentation in the default browser. Exit any running desktop instance (including a test build launched from `desktop/release/win-unpacked`) before installing a newer build over it; the previous API configuration, canvases, assets, generation history, theme and UI settings must survive. Fresh installs and upgrades must not show the false "cannot be closed" or "cannot open Uninstall Infinite Canvas.exe for writing" dialogs; if the app is running, the installer should ask to close it and continue. Uninstalling should also keep `%LOCALAPPDATA%\infinite-canvas` until it is deleted manually. When switching from the browser version for the first time, configuration export/import, canvas export/import, or WebDAV sync should move the data across.

- Saved model selection: save a canvas node with a model, then remove its provider or remove that model while another video model remains the default. Generation, retry and pending-video recovery should keep the unavailable model selected and open configuration instead of sending a request to the default or first provider. Re-selecting a valid model should allow generation. Changing only the API key on the same provider should preserve the model; switching a config node from a valid image model to video should still use the video default.

While the request runs the dialog should show progress, and the request log button should list each request's model, params, prompt, system prompt, input reference image, and model output, with Copy JSON and Export ZIP actions. The model result should be cropped to its opaque bounds before creating the child node, and the dialog should stay on a completed page with a result preview and a log entry point until Done is clicked. If the request fails, the local cutout result should be used for the child node and the completed page should show the failure while the log keeps the error. With Transparent background off, the cutout should be filled with white. Confirming should create and connect a cutout child node to the right of the image node, sized to the result ratio; submitting without a box or brush strokes should be blocked with a hint.
- Image node resolution: the image node hover toolbar should show a Change resolution button. Confirming should create a child node with the new resolution to the right of the source and connect it, with the display size fitted to the new ratio; Confirm should be disabled while the size is unchanged.

Step 1 should create editable boxes over the original image plus a left element list, supporting drag-to-create on empty image space, move/resize, delete, and rename; selecting a list row or a box corner should highlight the other, and clicking inside a box should create a new box instead of selecting it. ## 图片分辨率尺寸表

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

| 宽高比 | 1K | 2K | 4K |
| --- | ---: | ---: | ---: |
| **1:1** | **1024 × 1024** | **2048 × 2048** | **2880 × 2880** |
| **2:3** | 1024 × 1536 | 1360 × 2048 | 2336 × 3520 |
| **3:2** | 1536 × 1024 | 2048 × 1360 | 3520 × 2336 |
| **4:3** | 1024 × 768 | 2048 × 1536 | 3312 × 2480 |
| **3:4** | 768 × 1024 | 1536 × 2048 | 2480 × 3312 |
| **16:9** | 1536 × 864 | 2048 × 1152 | **3840 × 2160** |
| **9:16** | 864 × 1536 | 1152 × 2048 | **2160 × 3840** |
| **21:9** | 2016 × 864 | 2688 × 1152 | **3840 × 1648** |
| **9:21** | 864 × 2016 | 1152 × 2688 | **1648 × 3840** |

待验收：

- 在画布和图像工作台逐项切换 3 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K 的 1:1。
- 所有 4K 预设提交时均不应触发本地总像素或最长边限制；生成和编辑请求、调用脚本应收到所选像素尺寸。
- 分辨率为自动时保留比例选择，比例为自动时禁用 W/H；手动输入 W/H 后，对齐开关仍应按原有方式工作。
- Gemini 请求应带 aspectRatio（所选比例）；分辨率选了 1K / 2K / 4K 时应按尺寸表带上 imageConfig.imageSize，选自动时不带。质量不参与分辨率换算，视频尺寸设置保持原有行为。
- 图像质量可选自动与 5 档（低 / 中 / 高 / 极高 / 最高），请求里的 quality 字段应与所选档位一致，且尺寸不随质量变化。
